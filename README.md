# packages/odoo-module: the official Odoo app `letsbot_connector`

This is the Odoo-side addon for the LetsBot × Odoo integration (master plan Phase 6b, decision 11.1 #6). It is free and LGPL-3,
and is meant for the Odoo Apps Store.

```
src/letsbot_connector/        ← EDIT HERE (single source for every series)
17.0/ 18.0/ 19.0/             ← generated by build.py = content of each store branch (do not edit)
build.py                      ← renders src → series folders (tokens: @@SERIES@@ @@LIST@@ @@CRON_EXTRA@@)
scripts/test_in_docker.sh     ← fresh DB + module tests in a throwaway odoo:<major> container
scripts/e2e_live.sh           ← live pairing + signed webhook round-trip against scripts/fake_letsbot.py
scripts/make_po.py            ← i18n/{ar,es,pt}.po from the exported .pot
LETSBOT-CONTRACT.md           ← what the LetsBot (Laravel) side must implement
SUBMISSION.md                 ← Apps Store checklist
```

## What it does

- **Settings → LetsBot WhatsApp**: *Connect* creates the integration user and an API key (standard
  `res.users.apikeys`, with expiry on 18/19) and hands both to LetsBot server-to-server. LetsBot then confirms over the
  external API with that key. The screen shows status, workspace and last contact, and has *Reconnect*, *Send test event* and *Disconnect*
  (revokes the key).
- **Signed webhooks**: an outbox (`letsbot.webhook.event`) is filled inside the business transaction by an
  `_inherit = "mail.thread"` create/write/unlink hook, then delivered by `ir.cron` after commit. Each delivery is signed with
  `X-LetsBot-Signature: t=…,v1=HMAC-SHA256(secret, "t.body")` and retried with backoff (8 attempts over about 1.9 days). 410 marks the connection revoked.
- **Contact smart button**: *WhatsApp (LetsBot)* opens the conversation URL template that LetsBot sent at pairing.

Version differences: the Python code is identical across series. The API-key expiry column (17 has none) and the `res.users`
group field (`groups_id` vs 19's `group_ids`) are detected at runtime. The XML differs only in `tree`/`list` and the cron's
`numbercall`/`doall` (17).

## Develop / test

```bash
python3 build.py                       # after every change in src/
python3 build.py --check               # CI: rendered trees up to date?
scripts/test_in_docker.sh 18           # module only (deps: base_setup, mail)
scripts/test_in_docker.sh 18 full      # + sale_management, account, stock, crm (business-model tests)
scripts/e2e_live.sh 18                 # live: real Odoo HTTP + cron ⇄ scripts/fake_letsbot.py (pair, webhook, disconnect)
```
`scripts/fake_letsbot.py` is a ~150-line stdlib reference of the LetsBot side of LETSBOT-CONTRACT.md (handoff,
landing + JSON-RPC confirm, signature verification, 410 for unknown tokens). The Laravel implementation should mirror it.
The script uses the `dev_default` docker network and the `db` service from `packages/odoo/dev/docker-compose.yml`
(postgres:16). It creates `letsbot_mod_test<major>[_full]` and never touches `lb_demo`. To drop the DB:
`docker exec dev-db-1 dropdb -U odoo letsbot_mod_test18`.

Tests (`src/letsbot_connector/tests/`): `test_webhook_signature`, `test_queue_retry`, `test_pairing`,
`test_pairing_rpc` (HttpCase: real `/jsonrpc` with the handed-off key, plus `/json/2` on 19) and `test_business_models`
(skipped when the apps aren't installed).

Translations: `i18n/letsbot_connector.pot` is exported from a real install
(`odoo -d <db> --i18n-export=letsbot_connector.pot --modules=letsbot_connector`). `ar.po`, `es.po` and `pt.po` are
generated from it by `scripts/make_po.py`.
